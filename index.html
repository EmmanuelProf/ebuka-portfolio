APEX Sales Automation Suite

3 workflows. 46 nodes. A full sales pipeline — from first contact to signed proposal — running without a single manual step.

// sales-automation

Manual sales ops,
replaced.

A sales team was manually qualifying every inbound lead, writing every follow-up email by hand, and drafting proposals from scratch each time. Hours of work per day, inconsistent results, leads falling through the cracks.

Workflows3
Total nodes46
StatusLive
Stackn8n · Airtable · Gmail · Slack · OpenRouter · Google Docs · Notion
APEX #1 — Lead Qualification 13 nodes

Lead Qualification & CRM Auto-Update

  • Contact form fires a webhook — immediate 200 OK back to the user, then processing runs in parallel
  • Lead data cleaned and enriched: first name extracted, business vs personal email identified, team size mapped to a numeric signal
  • Claude 3.5 Haiku via OpenRouter returns a strict JSON: score 0–100, tier (Hot/Warm/Cold), primary pain point, recommended action, deal value estimate
  • Switch node routes: Hot → Airtable + instant Slack alert (#sales, score, pain point, deal value, "follow up within 2 hours")
  • Cold leads → personalised acknowledgement email via Gmail
  • Every lead logged to Google Sheets — 13 fields, regardless of tier
APEX #2 — Follow-Up Sequence 21 nodes

Reply-Aware Follow-Up Engine

  • Watches the Google Sheet — the moment a hot or warm lead is logged, a 7-day sequence begins
  • Day 1: wait → check Gmail API for a reply → no reply → send value prop email with Calendly link
  • Day 3: check again → no reply → send social proof email
  • Day 7: check one final time → no reply → send soft close
  • At every checkpoint: if resultSizeEstimate > 0 from Gmail API → sequence stops immediately
  • No chasing people who already said yes

AI Proposal Generator

Aurelius Customer Support Agent v2

78 nodes. One workflow. The difference between a chatbot and an autonomous support system.

// ai-agent · 78-nodes

This is not
a chatbot.

A chatbot answers questions from a script. Aurelius is an autonomous support system — it remembers every conversation, understands context, classifies intent, routes to the right logic, and only involves a human when it genuinely needs to.

Nodes78
Deployed onTelegram
MemoryMem0
StatusLive
Persistent Memory via Mem0

Before every response, Aurelius queries Mem0 for the user's full history. After every response, the conversation is written back. The next time they message — 5 minutes or 5 weeks later — it picks up exactly where it left off.

Intent Classification & Routing

Every message is classified before any response is generated. The classification reads message content and memory context together. "That didn't work" means something completely different depending on the last 3 messages.

Multimodal Input

Handles text, voice notes, and images natively on both channels. Users interact naturally — the system adapts to whatever they send.

Smart Escalation

When it can't resolve something, it packages the full conversation, memory summary, every attempted resolution step, and a suggested next action — then sends it to the human queue. The agent opens the ticket and immediately has the full picture.

Dual Deployment

Deployed on Telegram. The routing logic, memory layer, and escalation system all run through a single workflow entry point.

78 Nodes

Each one is a discrete operation — an API call, a decision branch, a data transformation, a memory read or write. The complexity is what makes it reliable. Simpler systems break on edge cases. This one was built to handle them.

Nova — Shopify AI Support Agent

37 nodes. Seven intent paths. A support system that actually resolves issues instead of deflecting them.

// ai-agent · shopify · 37-nodes

Intent-first.
Not script-first.

Most Shopify support chatbots answer three questions then say 'please contact support'. Nova was built to classify intent before generating any response — and route to dedicated logic for each one.

Nodes37
Intent paths7
Deployed onShopify Chat
StatusLive
OpenAI Intent Classifier

Every incoming message hits an intent classifier before any response is generated. Returns structured JSON: intent category, confidence, and routing instruction. No assumptions — just classification.

Seven Dedicated Handlers

Greeting, FAQ, order lookup, return request, complaint, cancellation, and escalation each have their own OpenAI node with a purpose-built prompt. A complaint is handled differently from a return. The routing makes that precise.

Live Shopify Order Lookup

When a customer asks about their order, the workflow hits the Shopify API in real time. Actual order status, tracking, and delivery details — not a cached summary.

Human Mode Toggle

When an agent takes over, all subsequent messages route directly to Telegram. The AI steps aside completely. When the flag clears, it resumes. No message gets lost in the handoff.

Dual Escalation Alert

Escalations fire a Telegram alert and a Gmail notification simultaneously — with the full conversation thread and a suggested resolution packaged in. The human opens the ticket with complete context.

Webhook Response Architecture

Every path ends with a dedicated respond node. The customer gets a reply regardless of which branch fired — no silent failures, no timeouts, no dead ends.

Abandoned Cart Recovery Engine

22 nodes. Two entry paths. One rule — never email a customer who already bought.

// sales-ai · shopify · 22-nodes

Recover carts.
Not customers.

Most abandoned cart flows send the same generic template to every customer, ignore whether they've already purchased, and miss guests who don't provide an email at first checkout. This one doesn't.

Nodes22
Entry paths2
StackShopify · OpenAI · Gmail · Google Sheets
StatusLive
Dual Webhook Entry

Fires on both checkout create and checkout update events. The Switch node handles both — create starts the abandonment flow, update catches the edge case where a guest provides their email after the initial checkout.

1-Hour Completion Check

After detecting an abandonment, the workflow waits one hour then checks Google Sheets to confirm the cart is still open. If the customer completed the purchase in that window, the recovery email never sends.

AI-Personalised Recovery Emails

OpenAI writes a personalised recovery email using the cart contents and customer name from the Shopify payload. Not a generic template — the email references what they were actually about to buy.

Full Logging via Google Sheets

Every event is logged: abandonment detected, email sent, recovery sent, order completed. Both paths write to the same sheet with 13 status fields — full visibility across the entire funnel.

Independent Parallel Paths

The create path and update path each run the full recovery sequence independently. No shared state between them — which means the email edge case (guest provides email late) is handled without breaking the main path.

Smart Completion Detection

The workflow looks up the cart token in Google Sheets when a Shopify order is placed and marks it completed. This is the check that prevents sending a recovery email to someone who already converted.

Agent Reply + Chatbot Bridge

8 nodes. No database. The infrastructure that makes human handoffs invisible to the customer.

// conversational-ai · polling · 8-nodes

The seam between
AI and human.

When Nova escalates to a human, that agent replies via Telegram. Getting that reply back to the customer on Shopify chat — without visible delay or switching interface — requires a polling bridge. This is it.

Nodes8
PatternWebhook polling
State storagen8n static data
StatusLive
Polling Architecture

The main chatbot holds an open webhook that waits for a reply with a specific session ID. This workflow stores the reply the moment the agent sends it — the poll immediately resolves and delivers it to the customer.

Session ID Validation

Every incoming Telegram message is checked for a valid session ID before storage. Invalid or missing IDs get an error message back to the agent immediately — no silent misrouting, no reply landing in the wrong customer's session.

Instant Agent Confirmation

Once the reply is stored, Telegram sends a confirmation back to the agent. They know the message was delivered without having to ask. Invalid replies also get feedback so the agent knows to retry.

Zero External Infrastructure

No Redis, no external database, no extra services. n8n's static data handles the reply storage. The simplest solution that works reliably at the session scale this system operates at.

Invisible Handoff

From the customer's perspective, the conversation continues in the same Shopify chat window. There's no 'you're being transferred' message, no interface change — just continuous conversation.

Part of a Larger System

This workflow doesn't stand alone — it's the reply layer of the Nova support system. Three workflows (Nova, Abandoned Cart, Agent Reply Bridge) form a complete Shopify customer operations stack.
